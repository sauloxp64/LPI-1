### 104.3-001 | unica | 1
ref: 101:p.483
tags: mount, listar
O que o comando `mount`, executado sem nenhum argumento, exibe?
= Os sistemas de arquivos montados no momento, no formato `origem on destino type tipo (opções)`
- O conteúdo do arquivo /etc/fstab, com uma linha para cada sistema de arquivos configurado
- Todas as partições detectadas pelo kernel, estejam elas montadas ou não
- Uma mensagem de uso, pois mount exige dispositivo e ponto de montagem
> Sem argumentos, `mount` lista o que está montado agora, lendo a tabela de montagens do kernel, em linhas como `proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)`.
> O conteúdo do fstab é mostrado com `cat /etc/fstab`; partições não montadas aparecem em `lsblk` ou `blkid`. Com `-t tipo` a lista pode ser filtrada por tipo de sistema de arquivos.

Qual é a ordem correta dos seis campos de cada linha ativa do arquivo /etc/fstab?

- ponto de montagem, dispositivo, tipo, opções, dump, pass

- dispositivo, ponto de montagem, opções, tipo, dump, pass

### 104.3-003 | unica | 2
ref: 101:p.487, 101:p.497
tags: fstab, noauto, mount -a
O arquivo /etc/fstab contém a linha abaixo. O que acontece quando o root executa `mount -a`?

```
/dev/sdb1  /data  ext4  noatime,noauto,async  0  0
```
= O sistema de arquivos não é montado, pois a opção noauto exclui a linha de `mount -a`
- Ele é montado em /data, pois noatime e async são opções válidas para o tipo ext4
- Ele é montado somente leitura, pois noauto equivale a uma montagem restrita
- Ele não é montado, pois falta a opção defaults, obrigatória em toda linha do fstab
> `mount -a` monta todas as entradas do fstab, exceto as que contêm `noauto`; a mesma regra vale para a montagem automática no boot. Uma entrada noauto continua válida e pode ser montada manualmente com `mount /data`.
> `noauto` não muda leitura/escrita (isso é `ro`/`rw`) e `defaults` é apenas um atalho, não uma obrigação.

### 104.3-016 | unica | 2
ref: 101:p.487
tags: fstab, pass, fsck
Qual é a função do sexto campo (pass) de uma linha do /etc/fstab?
= Definir a ordem de verificação do sistema de arquivos com fsck na inicialização; 0 desativa a verificação
- Informar ao comando dump se o sistema de arquivos deve entrar nas cópias de segurança
- Indicar a prioridade com que o sistema de arquivos é montado em relação aos outros
- Limitar o número de tentativas de montagem antes de o boot prosseguir sem o volume
> O campo `pass` (fs_passno) define a ordem do fsck no boot: 0 não verifica, 1 é reservado ao sistema raiz e 2 aos demais. Confirmado em `man fstab`.
> A decisão de entrar em backup do `dump` é do quinto campo (dump). A ordem de montagem segue a posição no arquivo (e dependências), e não há campo para contar tentativas.

> `-L` (ou `--label`) indica o rótulo e `-U` (ou `--uuid`) indica o UUID. Equivale a usar `mount LABEL=dados /mnt/dados`. Testado: com um rótulo inexistente, o mount responde "can't find LABEL=...".

### 104.3-031 | lacuna | 1
ref: 101:p.483-484, 101:p.497-498
tags: mount, -t, filtro
Qual comando `mount` lista somente os sistemas de arquivos dos tipos ext3 e ntfs que estão montados no momento (informe os tipos separados por vírgula, sem espaços)?
= mount -t ext3,ntfs
= mount -t ntfs,ext3
= mount --types ext3,ntfs
= mount --types ntfs,ext3
= mount -l -t ext3,ntfs
= mount -t ext3,ntfs -l
> Com `-t`, o `mount` sem outros argumentos filtra a listagem pelo tipo; vários tipos são separados por vírgula, sem espaços, e a ordem não importa. Testado com `mount -t proc,tmpfs`, que lista apenas esses dois tipos. (`findmnt -t ext3,ntfs` faz algo parecido, mas o enunciado pede o comando `mount`.)

### 104.3-032 | lacuna | 1
ref: 101:p.489
tags: lsblk, UUID, LABEL
Qual opção curta do `lsblk` exibe de uma vez as informações do sistema de arquivos (tipo, rótulo, UUID, espaço livre e ponto de montagem), sem que seja preciso listar colunas com `-o`? `lsblk ____ /dev/sda1`
= -f
= --fs
> `lsblk -f` (ou `--fs`) é o atalho para as colunas de sistema de arquivos: FSTYPE, FSVER, LABEL, UUID, FSAVAIL, FSUSE% e MOUNTPOINTS (testado no util-linux 2.38). Sem essa opção, o lsblk mostra colunas como NAME, SIZE, TYPE e MOUNTPOINTS, sem rótulo nem UUID.
> Também seria possível obter o UUID com `lsblk -o NAME,UUID`, mas aí as colunas são escolhidas uma a uma; o enunciado pede o atalho que dispensa o `-o`.
