```

```
= A busca termina sem consultar o DNS, e o nome não é resolvido
- O DNS é consultado normalmente, pois o nome não foi achado no arquivo

> O `dig` exibe a resposta completa, dividida em seções (pergunta, resposta, autoridade, informações adicionais), com flags e estatísticas. O `host` produz saída resumida, o `getent` mostra o resultado do resolvedor sem detalhes de DNS e o `ping` não faz consultas DNS detalhadas.

### 109.4-036 | multipla | 2
ref: 102:p.487-489, 102:p.496

Quais comandos consultam apenas o DNS, sem passar por /etc/nsswitch.conf nem por /etc/hosts?
= host
= dig
= nslookup
- getent hosts

> `host`, `dig` e `nslookup` são clientes DNS: enviam a pergunta direto ao servidor DNS. `getent hosts`, `ping` e `curl` usam o resolvedor da biblioteca C e seguem a ordem de `/etc/nsswitch.conf`, consultando `/etc/hosts` antes do DNS no padrão `files dns`.

### 109.4-038 | multipla | 2
ref: 102:p.483-485
tags: nsswitch
Quais afirmações sobre o arquivo /etc/nsswitch.conf estão corretas?
= A coluna da esquerda de cada linha é o banco de dados (hosts, passwd, group...)
= As fontes de cada linha são consultadas da esquerda para a direita
= Texto após # é comentário e é ignorado pelas funções de resolução
- Cada linha traz os endereços IP dos servidores DNS, no lugar de /etc/resolv.conf
- A ordem das fontes de hosts é fixa (files e dns) e não pode ser alterada
- O arquivo afeta apenas a resolução de nomes de host e não a de usuários e grupos
> O arquivo é organizado em colunas: banco de dados e fontes (`files`, `dns`, `nis`, `resolve`...); colunas entre colchetes, como `[NOTFOUND=return]`, acrescentam lógica condicional à fonte à esquerda. Ele vale para vários bancos, não só para `hosts`, e a ordem é livremente alterável.

### 109.4-039 | multipla | 3

Quais comandos getent são válidos?
